## 1. Developer-side Blender sources (developer.blender.org, projects.blender.org, code.blender.org, Blender Studio, Blender Conference)

### Takeaway
Developer docs (release notes with "Compatibility" sections, module pages, GPU/platform policy) are CC-BY-SA 4.0 and are the single highest-value, legally cleanest non-manual source; Blender Studio content is CC-BY by default (per-project exceptions). projects.blender.org (Gitea) holds the richest per-GPU bug evidence, but is a load-sensitive Gitea instance that has had crawler trouble, and was unreachable from here. The Blender Foundation's docs.blender.org robots.txt explicitly sets `ai-train=no`, `use=reference` and leaves `ai-input` (RAG) unset, which is the reference policy to expect on other blender.org properties.

### Cited Findings
- **docs.blender.org robots.txt [VERIFIED]**: Cloudflare-managed block with `User-agent: *` / `Content-Signal: search=yes,ai-train=no,use=reference` / `Allow: /`; header text says signals are "EXPRESS RESERVATIONS OF RIGHTS UNDER ARTICLE 4 OF THE EUROPEAN UNION DIRECTIVE 2019/790"; defines `ai-input` as "inputting content into one or more AI models (e.g., retrieval augmented generation, grounding...)" and states that if a signal is absent "the website operator neither grants nor restricts permission". **`ai-input` is absent**, so RAG use is neither granted nor restricted by the signal; `use=reference` is set. Named bots fully disallowed: Amazonbot, Applebot-Extended, Bytespider, CCBot, ClaudeBot, Diffbot, Google-Extended, GPTBot, omgili, anthropic-ai, Claude-Web, cohere-ai, MistralAI-Training, meta-externalagent, GoogleOther, Baiduspider, PetalBot, Awario bots, Google-CloudVertexBot, QualifiedBot, Cotoyogi, ICC-Crawler, atlassian-bot, FishBot, BorderxBot, NavuBot, SemrushBot-SWA, WARDBot, magpie-crawler, KimiBot, CitibotSiteCrawler. Second `*` group: `Disallow: /*/2.79/`, `Allow: /`, `Sitemap: https://docs.blender.org/sitemap.xml`. — [docs.blender.org/robots.txt](https://docs.blender.org/robots.txt)
  - Implication: a custom Scrapy UA (e.g. "G7B-Amatista-bot") is not in the deny list, but spoofing or using a listed UA would violate it; content must not be used for fine-tuning (ai-train=no).
- **docs.blender.org sitemap [VERIFIED]**: `sitemap.xml` (2.5 KB) only lists top-level entry points (`/api/`, `/manual/{de,en,es,fi,fr,it,ja,ko,...}/dev/`), not page URLs; `/manual/es/latest/sitemap.xml` returns 404. So `objects.inv` remains the right page enumerator. `https://docs.blender.org/manual/es/latest/objects.inv` → 200 (168 KB); `https://docs.blender.org/api/current/objects.inv` → 200 (193 KB). — [docs.blender.org/sitemap.xml](https://docs.blender.org/sitemap.xml)
- **Manual license [VERIFIED]**: Spanish manual footer states "CC-BY-SA 4.0 Int. License". — [docs.blender.org/manual/es/latest/](https://docs.blender.org/manual/es/latest/)
- **Developer docs license [SECONDHAND]**: "The content of the Blender Developer Documentation is available under a Creative Commons Attribution-ShareAlike 4.0 International License, or any later version"; attribute "Blender Developer Documentation Team"; logos, trademarks, icons, source code and Python scripts excluded. Release notes live in the same repo (`docs/release_notes/`), so they most likely fall under the same license (not explicitly confirmed). — [developer.blender.org/docs/license](https://developer.blender.org/docs/license)
- **Developer docs source repo [SECONDHAND]**: the developer docs are a Git repo hosted on projects.blender.org (a fork is visible at `projects.blender.org/.../blen_devdocs`), meaning they can be ingested as Markdown via `git clone` instead of HTML crawling. — [projects.blender.org/Ozay-Vaizoglu/blen_devdocs](https://projects.blender.org/Ozay-Vaizoglu/blen_devdocs)
- **projects.blender.org load / crawler history [SECONDHAND]**: Blender infrastructure issue "Gitea server running out of disk space due to archive downloads" (#29): an unidentified client repeatedly requested ~500 MB source archives; proposal to rate-limit and block known crawlers from archive endpoints; follow-up #32 "Deal with repo-archives bloat". — [issue #29](https://projects.blender.org/infrastructure/blender-projects-platform/issues/29); [issue #32](https://projects.blender.org/infrastructure/blender-projects-platform/issues/32)

- **projects.blender.org issues as hardware knowledge [SECONDHAND]**: bug reports carry system info + GPU + driver, e.g. "EEVEE Next: Blender freezing when render mode is selected #114597" (reporter ~1 fps on Intel iGPU; developers say EEVEE-Next "is not optimized for these kinds of devices" and are looking at low-end workability), "No response Intel Iris Plus Graphics #93257", "Blender crashes on start in weaker GPUs #39706"; old Phabricator URLs (developer.blender.org/T70922 "Intel Iris / Ice Lake GPU slow viewport performance", T91964 "Unsupported graphics card or driver error") redirect to projects.blender.org. — [#114597](https://projects.blender.org/blender/blender/issues/114597); [#93257](https://projects.blender.org/blender/blender/issues/93257); [#39706](https://projects.blender.org/blender/blender/issues/39706); [T70922](https://developer.blender.org/T70922)
- **Blender Studio license [SECONDHAND]**: Studio content is generally CC-BY, © Blender Foundation; each asset shows its own license snippet; default credit "(CC) Blender Foundation | studio.blender.org"; Sprite Fright pages cite CC-BY 1.0 and note some content stays copyright-limited until the film wraps; logos/trademarks and clearly third-party material excluded. — [Glass Half licensing](https://studio.blender.org/films/glass-half/pages/licensing); [Coffee Run licensing](https://studio.blender.org/films/coffee-run/pages/licensing); [Sprite Fright about](https://studio.blender.org/projects/sprite-fright/pages/about/); [Remixing](https://studio.blender.org/remixing/)
- **Blender Studio pipeline content exists publicly** (production pages, "vault", project pages). — [studio.blender.org/vault](https://studio.blender.org/vault/)
- **Blender Conference**: each talk has a page on conference.blender.org (e.g., 2025 presentation 4115), which gives structured metadata (title, speaker, abstract) without touching YouTube. — [conference.blender.org/2025/presentations/4115](https://conference.blender.org/2025/presentations/4115/)
- **YouTube transcripts (for Conference talks and all YouTube channels) [SECONDHAND]**: YouTube's CEO said downloading transcripts or video bits for model training "is a clear violation of our terms of service"; YouTube API developer policies forbid letting unauthorized third parties "access, use, or download" API data. — [PYMNTS](https://www.pymnts.com/?p=1884336); [YouTube Developer Policies guide](https://developers.google.com/youtube/terms/developer-policies-guide)

### Inferences
- Priority #1 new spider: developer.blender.org/docs (release notes per version, especially "Compatibility", "Platforms/GPU", "Python API" breaking-change sections). Best access path is `git clone` of the developer-docs repo (Markdown, MkDocs-style) rather than HTML; it is CC-BY-SA 4.0 (attribution + share-alike must be preserved in RAG citations). [PRIOR KNOWLEDGE, UNVERIFIED]: the site is MkDocs-Material, so a `sitemap.xml` and `search/search_index.json` likely exist at developer.blender.org/docs/ — verify.
- Because robots.txt on docs.blender.org sets `use=reference` and `ai-train=no` and omits `ai-input`, a RAG system that quotes with links (reference use) and never fine-tunes is the defensible posture; expect identical Cloudflare-managed rules on developer.blender.org / studio.blender.org (same operator), but this must be verified.
- projects.blender.org: [PRIOR KNOWLEDGE, UNVERIFIED] Gitea exposes `/api/v1/repos/blender/blender/issues?type=issues&labels=...&state=closed` JSON (paginated, `limit` ≤ 50) — far cheaper than HTML and avoids the archive endpoints that triggered the infrastructure issues. Filter by labels such as "Module/EEVEE & Viewport", "Platform/..." and "Interest/Intel/AMD/Apple" for GPU knowledge. Never request `/archive/*.zip|tar.gz`. With Zyte free plan (1-hour jobs), use incremental `since=` updates. User content in issues is not CC-licensed by default; treat as reference/citation only.
- code.blender.org (developer blog: design rationale, e.g., EEVEE Next, Vulkan backend) — no license or robots data could be obtained; WordPress sites usually expose `/feed/` RSS. [UNVERIFIED]
- Blender Conference: crawl conference.blender.org talk pages for metadata/abstracts; do NOT bulk-download YouTube captions. Use the YouTube Data API only for metadata (title, description, chapters), respecting quota and API ToS.

- No source found on whether projects.blender.org requires sign-in for any API listing pages after the 2025 crawler wave.

## 2. Community knowledge sources (Stack Exchange, Polycount, BlenderNation, blogs, 80.lv, ArtStation, Superhive/Gumroad, GitHub add-ons, Blender Artists, glTF/Godot/Unreal)

### Takeaway
Blender Stack Exchange is the densest Q&A corpus and is CC-BY-SA, but since 2024 its dump sits behind a login with extra (contested) anti-LLM terms and Stack's policies require consent for generative-AI use — high value, high legal friction; the cleanest path is the API for targeted questions with attribution, or skip. Commercial/editorial sites (80.lv, ArtStation, Superhive, CG Cookie, Blender Guru) are all-rights-reserved and increasingly hostile to AI (ArtStation blocks AI crawlers via Cloudflare by default); use only as linked references, not ingestion. GitHub add-on READMEs/issues and Discourse forums (already used) are the most accessible community sources.

### Cited Findings
- **Stack Exchange dump changes [SECONDHAND]**: since July 2024 the dump requires login and agreement that it is for personal use and not for projects that restrict others; Stack "reserves the right to deny me access to future downloads" if it is distributed to train an LLM; critics note CC BY-SA 4.0 forbids added restrictions. The June 2023 dump was skipped to add "guardrails". — [devclass 2024-07-30](https://www.devclass.com/development/2024/07/30/stack-exchange-restricts-access-to-dump-of-user-contributed-data-critics-complain-this-contradicts-license/1625192); [heise](https://heise.de/-9823083); [jlericson, The data dump diversion](https://jlericson.netlify.app/2023/06/19/data_dump)
- **Dumps continue in 2025 [SECONDHAND]**: Academic Torrents lists `stackexchange_20250331` (license "Various versions of CC-By-SA", license.txt in root) and a 2025-12-31 dump; the 2025-06-30 dump was reported to contain **watermarks with bogus data entries** — check the community known-watermarks list before use. — [Academic Torrents 2025-03-31](https://academictorrents.com/details/128a4d5b12d7738f9ab63e86c5b441c221fa8668); [Academic Torrents 2025-12-31](https://academictorrents.com/details/0d1d597fa7809f0e85f127b5eb3088219ddbad39); [ArchiveTeam wiki](https://wiki.archiveteam.org/index.php/Stack_Overflow)
- **Stack's AI stance [SECONDHAND]**: Stack blocks hosted commercial applications using community content without attribution and pursues paid "socially responsible" commercial access; has a "Consolidated Responsible AI policy"; a (low-reliability, undated) summary says automated collection for generative-AI use needs express prior written consent and an API key does not grant it, and the dump is "free for non-commercial use". — [Stack Overflow blog 2024-09-30](https://stackoverflow.blog/2024/09/30/ongoing-community-data-protection/); [Consolidated Responsible AI policy](https://policies.stackoverflow.co/company/consolidated-responsible-ai-policy); [techbloat (low reliability)](https://www.techbloat.com/?p=1950639)
- **Superhive (formerly Blender Market) [SECONDHAND]**: Blender Artists thread "Creators, starting today Superhive sells your products to AI" reports a paragraph about opting out of "bulk AI training set orders" in a holiday sales email (community commentary, not policy text); individual vendor licenses often forbid use for generative-AI training. — [Blender Artists thread](https://blenderartists.org/t/creators-starting-today-superhive-sells-your-products-to-ai/1656000); [Superhive rename post](https://superhivemarket.com/posts/beyond-business-as-usual-a-new-name-for-blender-market)

- **80.lv ToS [SECONDHAND, partial]**: talent ToS forbids circumventing "security-related features of the Site that prevent or restrict use or copying of any content"; full main ToS text not retrieved, so no explicit scraping clause confirmed. — [80.lv terms-of-use](https://80.lv/terms-of-use); [80.lv talent terms](https://80.lv/talent/terms-of-use)
- **Polycount wiki [SECONDHAND]**: no license statement found; a forum post by Eric Chadwick says wiki BaseMesh assets are free with attribution (covers only that page); the older wiki "went fallow". — [Polycount forum comment](https://polycount.com/discussion/comment/1785110)

Repo license not confirmed by search. — [manual 3.5 glTF page](https://docs.blender.org/manual/en/3.5/addons/import_export/scene_gltf2.html); [repo mirror listing](https://github.com/donmccurdy/glTF-Blender-IO)

### Inferences
- **Blender Stack Exchange verdict: high value / medium-high legal risk.** Content is CC-BY-SA (attribution + share-alike), but Stack's ToS/policies add consent requirements for generative-AI use; for a commercial-leaning education platform, either (a) request permission/commercial licence, or (b) restrict to the official API (api.stackexchange.com, `site=blender`, filter by tags like `performance`, `gpu`, `maya`, `import-export`, `workflow`) with low volume and attribution, treating it as reference retrieval. Do not use the 2025-06-30 dump without de-watermarking. [PRIOR KNOWLEDGE, UNVERIFIED]: API quota is 300 req/day without key, 10,000/day with key; robots.txt allows general crawling of /questions but blocks many AI UAs — verify.
- **Discourse (Blender Artists, DevTalk) — keep and extend**: [PRIOR KNOWLEDGE, UNVERIFIED] Discourse exposes `/c/<category>.json`, `/t/<id>.json`, `/latest.rss`, `/c/<cat>.rss` — use JSON, not HTML; target categories "Support > Technical Support", "Hardware", "Tutorials", "Español/Spanish", "Other software"; DevTalk "Feedback" threads on Vulkan/EEVEE performance. Forum posts are owned by authors (no CC license) → reference-only RAG with links.
- **GitHub add-ons (BlenderKit, Sverchok, glTF-Blender-IO, Node Wrangler now in Blender extensions repo)**: best access is GitHub REST/GraphQL API or `git clone` for READMEs/docs/wiki; licenses are per repo (most Blender add-ons are GPL because they link bpy; docs may be separate). Issues (user content) = reference only. Hard Ops is commercial/closed — docs only on its vendor site; low priority.
- **80.lv, ArtStation, CG Cookie, Blender Guru, Ryan King Art, BlenderNation**: all-rights-reserved editorial content; ArtStation actively blocks scrapers. Verdict: do not ingest bodies; at most index title + URL + short excerpt via RSS (BlenderNation and most WordPress blogs expose `/feed/` [UNVERIFIED]) so RAG can point users to them. 80.lv breakdowns are uniquely valuable for pipeline knowledge but should be handled as link-outs.
- **Superhive/Gumroad add-on docs**: storefront pages are commercial; the AI-dataset controversy makes the creator community sensitive. Low priority; prefer the add-on's own docs site/GitHub when one exists.

## 3. Hardware / performance knowledge (Open Data, OpenBenchmarking, Phoronix, Puget, reviews, drivers, low-end guides)

### Takeaway
The best structured, legally clean per-hardware numbers are Blender Open Data (CC0, daily full snapshot + JSON/CSV export). OpenBenchmarking.org (Phoronix Test Suite) adds Linux-heavy, opt-in results. Puget Systems, Phoronix, Tom's Hardware and TechGage are all-rights-reserved editorial — reference only. Real low-end (Intel iGPU, 8 GB) knowledge lives mainly in Blender bug tracker issues, the manual's GPU troubleshooting pages and forum threads, not in benchmark sites (which focus on high-end GPUs).

### Cited Findings
- **Blender Open Data [SECONDHAND]**: Search Data page exports JSON/CSV; download page offers "the daily snapshot of the entire opendata.blender.org dataset"; data "licensed under the CC0 - Creative Commons Zero license"; personal info (Blender ID username and hostname) removed; no documented public API found; platform source code at projects.blender.org/infrastructure/blender-open-data. — [opendata.blender.org/about](https://opendata.blender.org/about/); [opendata.blender.org/download](https://opendata.blender.org/download/); [blender-open-data repo](https://projects.blender.org/infrastructure/blender-open-data)
- **OpenBenchmarking.org [SECONDHAND]**: pts/blender (tracks upstream Blender) and system/blender (installed copy) profiles; uploads are opt-in via Phoronix Test Suite; profile pages report aggregate per-configuration metrics (one page: 87 public results since 2024-11-24); old profile license field "Free"; no public API found. Data shown is from late 2024 → possibly stale. — [pts/blender](https://openbenchmarking.org/test/pts/blender-1.4.0); [system/blender](https://openbenchmarking.org/test/system/blender); [perf page](https://openbenchmarking.org/performance/test/pts/blender/7ab9687dd0867b21f02bd88ac62d3a59ab395951)
- **Puget Systems [SECONDHAND]**: maintains "Hardware Recommendations for Blender" pages per workstation category, rendering benchmark hub, and "Rendering benchmarks vs reality" article (GPU/CPU rankings did not exactly match benchmarks but scaling was "in the ballpark"); 2025 Threadripper 9000 articles. High-end focus. — [Puget Blender recommendations](https://www.pugetsystems.com/solutions/3d-design-workstations/blender/hardware-recommendations/); [Rendering benchmarks vs reality](https://www.pugetsystems.com/labs/articles/rendering-benchmarks-vs-reality/); [rendering benchmarks](https://pugetsystems.com/rendering-benchmarks)
- **Official minimums [SECONDHAND]**: blender.org requirements: GPU with 2 GB VRAM and OpenGL 4.3 minimum, 8 GB VRAM recommended; Intel on Linux: Broadwell and newer; install latest vendor drivers. A third-party blog (renderahouse, 2026) claims Blender 5.0 added Vulkan 1.3 alongside OpenGL 4.3 with fallback to OpenGL — not confirmed in an official source. Older manual pages citing OpenGL 3.3 are outdated. — [blender.org requirements](https://www.blender.org/?p=157); [renderahouse blog](https://www.renderahouse.com/blog/blender-system-requirements)
- **Intel iGPU specifics [SECONDHAND]**: Blender manual GPU troubleshooting (Windows–Intel) warns 3rd/4th/5th gen Intel iGPUs crash on startup with the latest driver; manual troubleshooting recommends using the dedicated GPU and notes less support for older hardware since EEVEE (2.8). A Lenovo community post reports Blender 4.5 Vulkan working on 6th–10th gen Intel iGPUs on Linux but not on Windows 10. Intel support article on Iris Xe detection/driver reinstall. — [manual es 4.1 Windows–Intel](https://docs.blender.org/manual/es/4.1/troubleshooting/gpu/windows/intel.html); [manual nl 5.2 Other GPU](https://docs.blender.org/manual/nl/5.2/troubleshooting/gpu/windows/other.html); [Lenovo community](https://gaming.lenovo.com/general/post/new-blender-4-5-with-vulkan-support-works-on-older-6th-10th-gen-intel-nvkbgySOpuftTMb); [Intel support 000087442](https://intel.com/content/www/us/en/support/articles/000087442.html)
- No dedicated, authoritative "Blender on Iris Xe / 8 GB RAM" settings guide was found by search; results were bug reports and generic pages (search 2026-11-17).

### Inferences
- **Blender Open Data verdict: top priority, CC0** — download the daily snapshot (one file, fits a 1-hour Zyte job or better: a plain Azure Function/Data Factory download, no Scrapy needed) and derive tables "device → Cycles samples/min per scene per Blender version", including integrated GPUs and CPUs common in Mexican student laptops (Iris Xe, Radeon Vega/680M, Ryzen 5 mobile). This answers "how slow will my laptop be" with real numbers.
- **projects.blender.org issues + manual GPU troubleshooting pages + Blender Artists "Hardware" category** are the realistic corpus for low-end tuning (driver versions that crash, Workbench vs EEVEE, Vulkan backend toggle). Combine with release notes "Compatibility"/GPU sections from developer docs.
- **Puget/Phoronix/Tom's Hardware/TechGage**: copyrighted editorial; use RSS/title-level indexing and link-outs; extract no full text. Phoronix/OpenBenchmarking result pages are numerically useful but Linux/high-end biased.
- **Vendor driver release notes** (Intel/AMD/NVIDIA): usually list "Blender" in fixed-issues sections; proprietary but factual, reference-only; low volume, can be handled by a tiny targeted spider. [UNVERIFIED this session]
- **YouTube "Blender on low end PC"**: valuable tacit knowledge but transcript download conflicts with YouTube ToS (see §1); use metadata only or seek creator permission.

## 4. Maya / 3ds Max migration knowledge

### Takeaway
There is no official Blender "for Maya/Max users" guide; the canonical official pieces are the manual's keymap page (Industry Compatible keymap) and the original design task; real migration knowledge is in forum threads (Blender Artists, Polycount), Stack Exchange tags and paid keymap add-ons.

### Cited Findings
- Blender ships two built-in keymaps, Blender and "Industry Compatible", documented in the manual. — [manual keymap](https://docs.blender.org/manual/en/dev/interface/keymap/index.html)
- The Industry Compatible keymap design task (#54963) describes it as an alternative "for users who use Blender as part of their pipeline, in conjunction with industry standard apps" with Alt-drag orbit / MMB pan like Maya/Max; another task (T56991) covered updating Maya-style keymaps for 2.8. — [projects.blender.org #54963](https://projects.blender.org/blender/blender/issues/54963); [T56991](https://developer.blender.org/T56991)
- Users report limitations (loss of spacebar search, "still very non-standard"); a paid "Hybrid keymap" on Gumroad combines Industry Compatible navigation with Blender defaults; users ask for conversion guides that do not exist officially. — [Blender Artists thread p.3](https://blenderartists.org/t/industry-compatible-keymap/1155183?page=3); [2.8 Industry Compatible issues](https://blenderartists.org/t/2-8-industry-compatible-keymap-issues/1159123); [Hybrid keymap (Gumroad)](https://ninjadodo.gumroad.com/l/hybridkeys); [GameDev.tv thread](https://community.gamedev.tv/t/any-quick-conversion-guides-for-industry-standard-controls-planned/118847)
- Polycount has Max/Maya→Blender discussion threads. — [Polycount comment 2736995](https://polycount.com/discussion/comment/2736995); [Polycount comment 2722118](https://polycount.com/discussion/comment/2722118)

### Inferences
- Build migration knowledge from: manual keymap + FBX/USD/Alembic import-export manual pages (already crawlable, CC-BY-SA) + Blender Artists threads (search "Maya", "3ds Max", "Industry Compatible") + Blender SE tags (if SE access is resolved) + Polycount threads (reference-only).
- Autodesk help (help.autodesk.com) is proprietary; useful only for terminology mapping (e.g., Max "Edit Poly" ↔ Blender Edit Mode) via short excerpts/links. Not verified (host blocked).
- A curated, hand-written Spanish "equivalencias Maya/Max ↔ Blender" table authored by G7B would likely beat any crawled source in value and has zero license risk.

### Gaps
- Autodesk ToS / robots for help.autodesk.com not verified.
- No community "Blender for Maya users" long-form guide with an open license was identified.
